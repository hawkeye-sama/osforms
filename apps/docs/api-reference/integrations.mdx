---
title: 'Integrations'
description: 'OSForms integrations API: add Resend email, Google Sheets and webhook integrations to a form, update or delete them, check status, and send a test.'
---

These endpoints require your login session: the `ff_token` cookie, or the same JWT sent as `Authorization: Bearer <token>`. Integrations belong to a form, and each form has at most one integration of each type.

Integration configs are encrypted at rest with AES-256-GCM. Secrets (`apiKey`, webhook `secret`, Google `refreshToken`) are masked as `••••••••` whenever a config is returned.

## List a form's integrations

```
GET /api/v1/integrations?formId={formId}
```

```json
{
  "integrations": [
    {
      "_id": "64f1a2b3c4d5e6f7a8b9c0d1",
      "type": "EMAIL",
      "name": "Email notifications",
      "enabled": true,
      "createdAt": "2026-09-01T00:00:00.000Z",
      "updatedAt": "2026-09-01T00:00:00.000Z"
    }
  ]
}
```

## Create an integration

```
POST /api/v1/integrations
```

```json
{
  "formId": "671fa2b3c4d5e6f7a8b9c0aa",
  "type": "EMAIL",
  "name": "Email notifications",
  "config": {
    "provider": "resend",
    "apiKey": "re_xxxxxxxxxxxx",
    "from": "forms@yourdomain.com",
    "to": ["you@yourdomain.com"],
    "subject": "New Form Submission"
  }
}
```

**Types**: `EMAIL`, `WEBHOOK`, `GOOGLE_SHEETS`. A form has one integration per type, so posting a type the form already has replaces that integration (name, config, and `enabled`) instead of adding a second one. Returns `201` with `{ "integration": { "id", "type", "name", "enabled", "createdAt" } }`.

### EMAIL config

| Field       | Required | Description                                                                                        |
| ----------- | -------- | -------------------------------------------------------------------------------------------------- |
| `provider`  | Yes      | `"resend"`. (`sendgrid` and `smtp` are accepted but not implemented yet)                           |
| `apiKey`    | Yes      | Resend API key (`re_...`). Checked when an email is sent, not when the config is saved             |
| `from`      | Yes      | Sender address on your verified Resend domain                                                      |
| `to`        | Yes      | Array of recipient addresses, at least one                                                         |
| `subject`   | No       | Default `"New Form Submission"`. The form name is appended: `"{subject} - {form name}"`            |
| `autoReply` | No       | Confirmation email to the person who submitted. See [Resend](/docs/integrations/resend#auto-reply) |

### WEBHOOK config

| Field     | Required | Description                                                                   |
| --------- | -------- | ----------------------------------------------------------------------------- |
| `url`     | Yes      | Endpoint URL                                                                  |
| `method`  | No       | `POST` (default), `PUT`, or `PATCH`                                           |
| `headers` | No       | Extra request headers, e.g. `{ "Authorization": "Bearer ..." }`               |
| `secret`  | No       | Your signing secret. When set, requests carry an `X-osforms-Signature` header |

### GOOGLE_SHEETS config

Google Sheets is connected through Google OAuth from the form's **Integrations** tab, not with this endpoint. See [Google Sheets](/docs/integrations/google-sheets).

## Get an integration

```
GET /api/v1/integrations/{id}
```

Returns `{ "integration": { "_id", "type", "name", "enabled", "config", "createdAt", "updatedAt" } }`. Secrets in `config` are replaced with the literal string `••••••••`: `apiKey` for `EMAIL`, `secret` for `WEBHOOK`, and `refreshToken` for `GOOGLE_SHEETS`.

## Update an integration

```
PATCH /api/v1/integrations/{id}
```

```json
{
  "enabled": false
}
```

Updatable fields: `name`, `enabled`, `config`.

`config` **replaces** the stored config, so send the complete object. Whatever you send is encrypted and saved as-is.

<Warning>
  Don't PATCH back a config you got from `GET`. The masked `••••••••` would be
  saved as your real API key or secret, and the integration would start failing.
</Warning>

To keep a stored secret without resending it:

| Type            | Send                            | Effect                                                               |
| --------------- | ------------------------------- | -------------------------------------------------------------------- |
| `EMAIL`         | `"apiKey": "auto"`              | Reuses the API key already stored for the form's `EMAIL` integration |
| `WEBHOOK`       | `"secret": "__KEEP_EXISTING__"` | Keeps the current secret (or drops the field if none was set)        |
| `GOOGLE_SHEETS` | No keep value                   | Reconnect through Google OAuth instead                               |

## Delete an integration

```
DELETE /api/v1/integrations/{id}
```

Returns `{ "success": true }`.

## Test an integration

```
POST /api/v1/integrations/{id}/test
```

Runs the integration once with sample data (`Test User`, `test@example.com`, and a few more fields). No submission is created.

```json
{
  "success": true,
  "message": "Email sent via Resend"
}
```

If the integration fails, you get `400` with `{ "error": "Test failed", "message": "<provider error>" }`. If the test throws instead (for example a timeout or network error), you get `500` with `{ "error": "Failed to test integration", "message": "<error>" }`.

## Integration status

```
GET /api/v1/integrations/{id}/status
```

Returns `type`, `name`, and `enabled`. For Google Sheets it also returns `connectedEmail`, `spreadsheetId`, `spreadsheetUrl`, and `sheetName`.

Per-submission success or failure is in the [integration logs](/docs/api-reference/forms#integration-logs-for-a-submission).
